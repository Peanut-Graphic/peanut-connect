## Advisory addendum — CAT + MAX on this closure

**MAX (was the right thing done?):** "Merged but unreleased" was the only real problem and it was severely under-weighted before the release was cut — known vulns (bearer-in-HTML, plaintext key) sat live as v3.11.6 while the fixes idled in main. Cutting v3.13.0 was correctly the #1 action; the PR/issue/branch noise was never a release blocker. Both pre-tag verifications (bearer not in built output; A5 migrates existing keys on update, not just fresh installs) were the right gates and both passed. Verdict: **ship — done.**

**CAT (what's next?):** The deeper theme — *this is no longer a security problem, it's a distributed protocol with two independently-deployed implementations and (until now) no automated referee.* Angle A (shared signing vectors, now shipped both sides) is the highest-leverage durable guard. Remaining roams worth a backlog: a **protocol-version header** (`X-Peanut-Protocol`) so a future scheme bump fails loudly instead of as a cryptic "invalid signature"; the **A8b rollout via Hub-pushed flag** over the heartbeat (Hub flips `require_signed_requests` once it has confirmed N signed requests to a site — no manual per-site toggle); the **outbound edge→Hub direction is still bare Bearer** (inbound is HMAC-signed — a structural asymmetry); and **no key-rotation/revocation story** for a compromised or offboarded site (matters for Itron). *(Note: CAT's "self-updater zip integrity" and "nonce-burn TOCTOU" angles were read off a stale checkout — both are already fixed in 3.12.0/3.13.0.)*
